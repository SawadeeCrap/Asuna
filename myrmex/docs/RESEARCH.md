# Исследование: Hunyuan3D → Blender → музыка (Ableton / VCV) на MacBook Pro M4 Pro 24 ГБ

Состояние на сентябрь 2026. Всё, что ниже помечено «проверено», я запускал сам
(облачный Linux-контейнер, Blender 5.2.2 LTS и 4.5.14 LTS как Python-модули `bpy`,
на вашем тестовом GLB).

---

## 1. Главный вывод

Цепочка «сгенерировал в Hunyuan3D → сразу анимирую музыкой» не работает напрямую:
Hunyuan выдаёт **статичную скульптуру** (плотная треугольная сетка без скелета, часто
без UV). Между генерацией и музыкой нужны три этапа, и именно они определяют качество:

1. **Доводка ассета в Blender** (то, чего Hunyuan не делает): нормализация,
   ремонт сетки, ретопология/клетка деформации, UV, материалы.
2. **Авто-риг под произвольную морфологию** (человек, паук, насекомое, робот) —
   готовых локальных решений для Mac нет, поэтому сделан собственный.
3. **Процедурный мотор + поведенческий движок**, которые превращают музыкальные
   данные в физически правдоподобное, не повторяющееся движение.

## 2. Hunyuan3D сегодня

| Версия | Веса | Что важно для нас |
|---|---|---|
| Hunyuan3D-2.0 / 2mini / 2mv | открыты | форма + текстура; есть Mac-форки |
| **Hunyuan3D-2.1** (июнь 2025) | **открыты** | PBR-материалы (albedo/metallic/roughness); последняя открытая «большая» версия |
| **Hunyuan3D-Omni** (сент. 2025) | открыты | управление генерацией: **скелет/поза**, bbox, облако точек, воксели; ~10 ГБ VRAM |
| 2.5, 3.0, 3.1, PolyGen | **только облако/API** | лучше качество, квад-топология (PolyGen) |
| Hunyuan3D Studio | облако | сквозной конвейер вплоть до авто-рига (гуманоиды и «общие» персонажи) |

**На Mac (M4 Pro, 24 ГБ):** форма генерируется локально через MPS/MLX-форки
(`Hunyuan3D-2-Mac`, `Hunyuan3D-2.1-mac`, `Hunyuan3D-MLX`). Геометрии нужно ~24 ГБ,
текстурному проходу — около 48 ГБ, поэтому на 24 ГБ текстуры надёжнее делать в
облаке Hunyuan или **заменять look-dev'ом в Blender** (наш путь по умолчанию: у
вашего тестового ассета текстур нет вовсе).

**Что показал ваш тестовый GLB (проверено):**

- 1 499 976 треугольников, 749 928 вершин, одна замкнутая оболочка (manifold);
- нет UV, нормалей и текстур — только позиции (экспорт `pygltflib`);
- расслабленная A-поза, руки отделены от корпуса;
- **ноги слиты юбкой-карандашом** до середины бедра, каблуки, пучок волос слит со спиной;
- после децимации попадаются рёбра короче 0,1 мм — из-за них QuadriFlow в Blender
  отказывается работать (мы это чиним автоматически).

**Как генерировать персонажей, чтобы риг получался лучше:**

- нейтральная A/T-поза, конечности не касаются корпуса и друг друга;
- стопы/лапы стоят на земле; без подставки и постамента;
- для существ: ноги явно разделены; для «рабочей» формы — симметрия;
- Hunyuan3D-Omni позволяет задать позу скелетом — удобно для A-позы;
- юбки, плащи, длинные волосы — допустимы, но это слитые области: их движение даёт
  вторичная динамика, а не отдельная геометрия.

## 3. Авто-риг: что есть и что сделано

| Инструмент | Произвольная морфология | Локально на Mac | Замечание |
|---|---|---|---|
| UniRig (SIGGRAPH 2025, MIT) + преемник SkinTokens | да | **нет** (CUDA, ≥ 8 ГБ) | лучший открытый ML-риггер |
| Hunyuan3D Studio auto-rig | частично | нет (облако) | |
| Mixamo, AccuRIG | только гуманоиды | нет/частично | |
| Auto-Rig Pro | да, вручную по маркерам | да | платный |
| Spider Walker (Blender 5.2, авг. 2026, MIT) | только шагание пауков | да | нет смены походки, динамики тела, музыки |

**Сделано в проекте (проверено на вашем GLB):** морфологический анализ без ML:

1. геодезический центр поверхности (AGD по выборке FPS);
2. **дерево слияния** надуровневых множеств геодезического расстояния с упрощением
   по персистентности → кончики конечностей и места их сращивания;
3. отсев «шишек» (ягодицы, грудь) по вытянутости ветви;
4. классификация плана тела (двуногое/четвероногое/шести-/восьминогое/безногое);
5. подгонка скелета: геометрия там, где она однозначна (сужение лодыжки, запястья,
   изгиб локтя), **анатомические приоры** там, где её скрывает одежда (тазобедренные
   суставы внутри юбки);
6. **геодезические веса** с ограничением «кость сеет только из своей конечности»
   (рука не прилипает к рёбрам), расширенное смешивание в слитых областях (юбка).

Результат на вашем ассете: 22 кости с именами UE-манекена, веса, Corrective Smooth,
позы «шаг» и «жест» деформируются корректно — полностью автоматически за ~3 с.

## 4. Blender как этап доводки (Blender 5.2 LTS)

- **Blender 5.2 LTS** (июль 2026), Python 3.13. Изменения API, которые мы учли:
  слотовые Action (в 5.0 удалён `action.fcurves`), `BLENDER_EEVEE_NEXT` →
  `BLENDER_EEVEE`, композитор как node group, устаревание `use_nodes`.
  Код проекта проверен на 5.2.2 и 4.5.14.
- **Cycles на Apple Silicon:** Metal, аппаратная трассировка на M3/M4,
  GPU-денойз; в 5.2 — texture cache и режим Thin Wall у Principled BSDF.
- **Что Blender делает за Hunyuan:**
  - ремонт сетки (слияние вырожденных рёбер < 0,1 мм, починка manifold);
  - **ретопология QuadriFlow** (проверено: 27k квадов за ~60 с в контейнере);
  - **клетка деформации:** квад-клетка скинится и сглаживается, детальный меш
    следует за ней через Surface Deform — все детали Hunyuan сохраняются;
  - перенос деталей (Multires reshape) или запекание normal/AO/curvature;
  - Corrective Smooth (delta-mush) по маске суставов;
  - процедурные PBR-материалы (жидкий металл, хром, керамика) без UV;
  - студия, DOF, motion blur, AgX, композитинг.

## 5. Ableton

- Live 12.x; **Max 9** с объектом `v8` (современный JS; Live 12.2+).
- Live API: `get_all_notes_extended` (Live 11+), вероятности нот, MPE.
- **AbletonOSC** (MIDI Remote Script; UDP 11000/11001; Live 11+) — готовый мост к LOM.
- **Новое: Ableton Extensions SDK** — публичная бета с июня 2026, Node.js/TypeScript,
  нужен Live 12.4.5 Suite (beta); читает/редактирует треки, клипы, ноты, девайсы,
  автоматизацию. Перспективный официальный путь, но пока бета.
- **Файл `.als` — это gzip-XML**: темп, размер, треки, клипы (включая лупы),
  ноты, Drum Rack-пэды, автоматизация, локаторы. Это основа **офлайн-режима**:
  Live даже не нужно запускать.

Выбранная схема: офлайн — разбор `.als` (+ стемы WAV для аудиотреков);
живой режим — наш Remote Script, который шлёт партитуру и транспорт, а приёмник
сам восстанавливает точное время нот (джиттер UI-потока Live не влияет).

## 6. VCV Rack

- **VCV Rack 2.6.x** (последний релиз 2.6.3, март 2025); Rack 3 в разработке.
- Плагины — C++ SDK; в `process()` (аудиопоток) нельзя блокировать: сетевой
  вывод — через lock-free очередь и отдельный поток.
- Альтернативы без компиляции: `trowaSoft cvOSCcv` (CV↔OSC), `CV-MIDI` → IAC Bus.
- Патч `.vcv` — tar+zstd с `patch.json`; автосохранение — обычный JSON.

## 7. MCP

- Официальный Python SDK **v2** (`mcp` 2.2.0): `FastMCP` переименован в
  `MCPServer` (`from mcp.server import MCPServer`), спецификация 2026-07-28;
  отдельный пакет `fastmcp` 4.x. Наш сервер поддерживает v1 и v2.
- MCP — только интерфейс управления; движок работает и без него (CLI, Python, Blender).

## 8. Организм в духе Rev-9 (ваш второй промпт)

- **Isaac Sim 5.1/6.x и Isaac Lab не работают на macOS** — только Ubuntu/Windows +
  NVIDIA RTX (рекомендуют RTX 4080 16 ГБ, 32 ГБ ОЗУ).
- Isaac Lab 3.0 (бета) — мультибэкенд (PhysX, Newton, MuJoCo-Warp); **Newton на
  macOS работает только на CPU**.
- **Genesis** компилирует ядра под Apple Metal и содержит MPM/PBD/SPH — лучший
  нативный вариант для прототипа «активного материала» на M4 Pro.
- Реалистичный путь: прототип сети из 64–256 узлов на Mac (numpy/Genesis) →
  обучение RL в масштабе на арендованном NVIDIA GPU (Isaac Lab) → экспорт политики
  в ONNX → политика управляется тем же музыкально-поведенческим слоем, что и
  персонажи → рендер в Blender через Geometry Nodes (точки → объём → сетка,
  чёрный металл).

## 9. Техники процедурной анимации, на которых построен движок

- **Динамика второго порядка** (f, ζ, r — t3ssel8r, 2022): r < 0 = предвосхищение,
  r > 1 = перелёт; импульсы как «пинки» скорости.
- **Критически демпфированные пружины** (D. Holden, «Spring-It-On», 2021).
- **Soft IK** (A. Nicholas): колено не «щёлкает» у предела досягаемости.
- **Таз как перевёрнутый маятник**: высота ограничена досягаемостью опорной ноги —
  вертикальное покачивание, провал в двойной опоре и подъём пятки возникают сами.
- **Шаг по потребности**, а не по часам (идея Walknet, H. Cruse): нога шагает,
  когда отстаёт от своей опорной точки; ходьба, развороты, приставные шаги,
  остановки — из одного правила.
- **CPG / связанные осцилляторы Курамото** для многоногих и для «мягкого» захвата бита.
- **Привыкание/растормаживание** (биология) против механического повторения.
- Предсказатель грува по позициям в такте: предвосхищение, удивление, пропуск удара.
