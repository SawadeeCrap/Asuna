# Мозг морфологии

Автономный слой поверх движка организма. Он не даёт форме оседать: помнит, чем организм уже был, замечает, что повторяется, ищет формы, которых ещё не было, иногда доводит текущую форму дальше, а сильно позже возвращается к старой, но изменённой.

Рука и MIDI по-прежнему ведут. Мозг работает в отдельном процессе рядом с движком и не может его остановить. По умолчанию он **выключен**.

Код лежит в `src/myrmex/brain/`, песочница — `python morphology_brain_test.py`, тесты — `tests/test_brain.py`.

```
 рука (перчатка) ─┐                                   ┌─────────── процесс-воркер мозга ───────────┐
 Ableton / MIDI ──┼─► InputHub ─► LiveSession 120 Гц ─┤  отпечаток → память → новизна → кандидаты  │
 аудио, часы ─────┘        (как было)     │    ▲       │        → арбитр (детерминированный          │
                                          │    │       │          или Kev, если он запущен)          │
                                          │    └── решение: смесь форм, материал, событие,        │
                                          │        сила, сколько держать (раз в 7–20 с)            │
                                          ▼                           │ localhost HTTP (по желанию)
                                   движок организма                   ▼
                              (плавный переход сам)             kev.serve (MLX, Metal)
                                          │
                                          ▼  UDP 60 кадров/с (как было)
                                       Blender
```

## Как включить

- **Приложение**: страница *Creature* → группа **Morphology brain** → **On**.
  - *decides*: **Built in** (детерминированный арбитр, режим G) или **Kev (local server)** (режим F).
  - Ползунки Autonomy, Novelty, Persistence, Mutation, Returns, Memory; поле *Looks* — сколько раз в секунду мозг смотрит на тело.
  - Кнопки *Good form* / *Bad form* — твоя оценка текущей формы. Хорошая форма возвращается охотнее, плохая больше не возвращается.
  - Строка статуса показывает, что мозг сделал последним, сколько форм он помнит и сколько раз спросил Kev.
  - Журнал решений и пометок ложится в `~/Myrmex/brain/`.
- **MIDI** (страница MIDI, цели привязок):
  - пэды `brain` (вкл/выкл), `brain:good`, `brain:bad`;
  - CC `brain_autonomy`, `brain_novelty`, `brain_persistence`, `brain_mutation`, `brain_return`, `brain_memory` (0..1) и `brain_rate` (0..1 → 0.25..2 Гц).
- **Переменные окружения** читаются один раз при старте движка:
  - `MYRMEX_BRAIN_ENABLED=1`, `MYRMEX_BRAIN_MODE=G|F|…`, `MYRMEX_BRAIN_HZ=1`;
  - `MYRMEX_BRAIN_AUTONOMY`, `MYRMEX_BRAIN_NOVELTY`, `MYRMEX_BRAIN_PERSISTENCE`, `MYRMEX_BRAIN_MUTATION`, `MYRMEX_BRAIN_RETURN`, `MYRMEX_BRAIN_MEMORY` (0..1);
  - `MYRMEX_BRAIN_MEMORY_SIZE=96`, `MYRMEX_BRAIN_MIN_CONFIDENCE=0.2`;
  - `MYRMEX_BRAIN_KEV_URL=http://127.0.0.1:8009`, `MYRMEX_BRAIN_KEV_TIMEOUT=0.8`.

  Префикс `MYRMEX_` выбран, чтобы не путаться с собственными переменными Kev (`KEV_DTYPE`, `KEV_MODEL`…).
- **Kev** (по желанию, только локально):

  ```bash
  git clone https://github.com/jaredpalmer/kev && cd kev
  uv sync --extra serve
  uv run --extra serve python -m kev.serve --run jaredpalmer/kev-0.8b --port 8009
  ```

  Первый запуск скачивает базовую модель и адаптер с Hugging Face. Дальше сеть не нужна. Адрес не с этой машины и не из локальной сети мозг не примет: облачных API он не использует.

## Оценка (14 пунктов)

Источник правды — текущий репозиторий Kev (github.com/jaredpalmer/kev, коммит 5920c5f): README, карточки моделей, `kev/serve.py`, `kev/api.py`, `kev/mlx_model.py`. Всё, что про Myrmex, измерено здесь, на песочнице и на настоящих движках. Цифры Kev на Mac взяты из его README: скачать веса в этой среде нельзя (huggingface.co закрыт сетевой политикой, 403). Как измерить их у себя — в разделе [Kev на Mac](#kev-на-mac-как-замерить-d-e-f).

### 1. Что такое Kev

Семейство небольших открытых **моделей решений**: Kev-0.8B, 4B, 9B и 27B.

- 0.8B, 4B и 9B построены на Qwen3.5 (`-Base`) плюс LoRA r16 и pointer-head.
- 27B построена на пост-тренированной Qwen3.8-27B.
- Все реализуют контракт TypeSafe System One `POST /v1/systemone` у тебя на машине.

- **Вход**: одно *состояние* (JSON или текст) и несколько типизированных вопросов.
- **Выход**: распределение вероятностей на каждый вопрос за **один проход prefill**, без генерации текста.
- **Типы вопросов**:
  - `choice` — выбор из именованных вариантов, с уверенностью (p_max − 1/K)/(1 − 1/K);
  - `score` — ожидаемый уровень на упорядоченной шкале;
  - `noul` — p(да).
- **Калибровка**: вероятности откалиброваны одной температурой (у 0.8B T = 2.35). Порядок ответов она не меняет.
- **Вопросы изолированы** друг от друга и считаются над общим закэшированным состоянием.
- **Сервер** `kev.serve`: FastAPI, один поток модели, кэш префикса состояния. На Apple Silicon работает через MLX (Metal) в bf16, на NVIDIA — через CUDA.

Это **не Jev**: Jev — закрытая хостинговая модель TypeSafe. Kev работает локально, после разовой загрузки весов сеть ему не нужна.

### 2. Что Kev реально может здесь

Выбрать один из нескольких **заранее посчитанных и проверенных** кандидатов на превращение и оценить, насколько сильным оно должно быть. На входе — короткое структурированное описание: организм, его формы, недавняя история и контекст (музыка, рука). Это ограниченный типизированный выбор с вероятностями, ровно то, для чего Kev сделан.

Что он добавляет к детерминированному арбитру:

1. «Вкус» по словесным описаниям вариантов: «новое», «плавно», «необычно для него», «идёт за рукой».
2. Потом, после дообучения на твоих пометках *Good/Bad* и журналах решений, — **твой** вкус. Это единственное, чего детерминированный код сам не умеет.

Из коробки Kev морфологических решений не видел, как его шахматная демка, которая «не видела шахматной партии». Его выбор будет правдоподобным, но не опирается на геометрию. Точность 0.8B на новых источниках в его собственных бенчмарках — 0.648/0.697.

### 3. Чего Kev делать не должен

- Работать каждый кадр или каждый тик движка.
- Считать расстояния, новизну и геометрию: арифметика делает это точно и за микросекунды.
- Придумывать формы или операции: он только выбирает среди допустимых.
- Двигать вершины или параметры напрямую.
- Быть обязательным: организм живёт без него.
- Генерировать текст.
- Ходить в облако.
- Понимать уверенность как правильность.

### 4. Архитектура

Гибрид; схема вверху.

- **Движок** (120 Гц) остаётся детерминированной физикой и процедурой. Все переходы непрерывные и делаются им самим: латентная инерция, материал, частицы.
- **Рука и MIDI** действуют на движок напрямую каждый тик, как и раньше. Мозг их не перехватывает.
- **Мозг** живёт в **отдельном процессе** (свой интерпретатор Python, без Qt, аудио и движка) и связан с движком парой сокетов (`BrainLink` ⇄ `python -m myrmex.brain.worker`).
  - Раз в секунду тик движка отправляет снимок тела: смесь форм, до 160 точек, материал и число тел, около 2.3 КБ.
  - Когда ответ готов, адаптер записывает решение в **те поля, которые у движка уже есть**: цель латента `z_goal`, цель материала `mat_goal`, таймеры намерения (`intent_t`, `dwell`) и `trigger_event`. У v1 это `morph.dst` и `beh.dwell`.
  - Своих реакций движок не теряет: рывок на кик, уклонение, жесты.
  - Направление мозга возвращается после 4 с тишины в собственных целях движка, а после рывка на кик — через 1.2 с.
  - Без этого Spear, который на каждом кике заново ставит себе LANCE и сам к прежней форме не возвращается, весь дроп простоял бы копьём. Отсюда и было «LANCE 55% времени».
- **Внутри воркера** — память, новизна, генерация кандидатов и арбитр. Арбитр по умолчанию детерминированный. Kev — необязательный арбитр поверх него, по HTTP на localhost.

Почему процесс, а не поток:

- Тик движка на Python занимает 2–7 мс из 8.33 мс (spear в среднем 5.6 мс, p95 10.4 мс). Поток с геометрией кандидатов и JSON делил бы с ним GIL.
- Процесс GIL не делит, а его падение или зависание не трогает организм.

Почему пара сокетов, а не `multiprocessing` spawn: spawn заново импортирует главный модуль родителя, а в приложении это окно Qt. Пара сокетов — это то же, что `multiprocessing.Pipe`, но без этой ловушки.

### 5. Хватит ли Kev-0.8B

**Да, в роли, которая ему здесь отведена**: выбрать один из 6 заранее оценённых кандидатов, когда детерминированный арбитр остаётся полом. Все измеримые выигрыши в исследовании (ниже) даёт уже режим G без Kev. Kev должен заработать своё место на бенчмарке D/E/F на Mac.

- **Kev-4B.**
  - На Mac в 5 раз медленнее: 721 мс против 149 мс на новое состояние, 136 против 28 мс из кэша (M5 32 ГБ, 5 вопросов, около 270 токенов).
  - Около 8 ГБ весов в bf16; README рекомендует Mac на 32 ГБ.
  - На M4 Pro 24 ГБ вместе с Blender работать будет, но впритык по памяти.
  - Его выигрыш в точности (0.65 → 0.82 на новых источниках) важен для задач на знания, а не для ограниченного эстетического выбора.
  - Имеет смысл только после того, как 0.8B покажет пользу на D/E/F.
- **Kev-9B** — Mac на 32 ГБ, 24 ГБ не хватит. **Kev-27B** — нет пути на Mac вообще.
- **Квантизация (4/8 бит)**:
  - в Kev её нет: сервер грузит базу и адаптер в bf16 (или fp32 через `KEV_DTYPE=fp32`);
  - MLX умеет квантизовать сам, но температура калибровки и pointer-head подогнаны под bf16/fp32. После квантизации калибровку пришлось бы проверять заново. Сейчас не нужно: 0.8B в bf16 — это около 1.6 ГБ весов.
- **Metal**: да, через MLX на Apple Silicon, выбирается автоматически.
- **Длина контекста**: Kev учился на состояниях до 384 токенов. Наш запрос (организм, формы, сводка памяти и два вопроса) укладывается в этот предел.
- **Загрузка**: веса скачиваются один раз при первом `--run`. Дальше модель держится в памяти сервера, запросы «тёплые». Держи сервер запущенным всё выступление.
- **Дообучение** имеет смысл позже.
  - Мозг ведёт журнал `~/Myrmex/brain/<организм>-<дата>.jsonl`. В нём каждое решение (текущая форма, кандидаты с новизной и полезностью, выбор, кто выбрал, уверенность Kev, сводка памяти) и пометки Good/Bad с пэдов `brain:good` и `brain:bad`.
  - Из этого журнала собирается JSONL для `kev.train --init_from jaredpalmer/kev-0.8b`. Только тогда у Kev появится преимущество перед детерминированным арбитром.
  - README Kev предупреждает: при 400 записях выигрыш в пределах шума. Нужны тысячи решений.

### 7. Задержки

- **Снимок → решение без Kev**: медиана около 8 мс (это граница тика 120 Гц), p95 около 25 мс, худшее около 40 мс.
  - Считается само решение 1.4–1.8 мс в медиане; p95 17 мс — это ход с кандидатами и их геометрией.
  - Сериализация около 15 мкс, сообщение 2.3 КБ.
- **С Kev** добавляется его время модели:
  - 0.8B — примерно 150 мс на новое состояние и 30 мс из кэша (M5, README);
  - запрос с таймаутом 0.8 с. Опоздавший ответ отбрасывается, решает детерминированный арбитр.
- **Для морфологии это неважно**: переход длится 1–3 с, решение держится 4–14 с.
- **Для руки и MIDI задержка не меняется** (+0 мс): их путь мозг не трогает.

### 8. Частота решений

У мозга три часов.

1. **Движок, 120 Гц**: физика и непрерывная деформация.
2. **Взгляд мозга, 1 Гц**:
   - обновить память и решить, пора ли что-то менять;
   - стоит около 0.1 мс в воркере и около 2 мкс в тике движка.
3. **Решения — 2.7 в минуту при автономии 0.5, 5.4 при 0.75, до 9 при 1.0** (свип автономии):
   - там, где движок и так выбирает следующую форму (его `dwell` 4–10 с), мозг забирает этот выбор с вероятностью, равной автономии;
   - при автономии выше 0.6 мозг меняет форму и между этими точками, раз в 5–14 с;
   - Kev спрашивается только здесь.

Почему не 2–5 или 5–10 Гц:

- Тело не может выразить решения быстрее: время релаксации латента τ = 0.8 + 3·rigidity·(1.2 − fluidity) ≈ 1–3 с, а сама форма держится 4–10 с.
- Свип частоты (ниже) показывает, что метрики исследования от 0.25 до 4 Гц одинаковы, а CPU мозга растёт с частотой. Мозг заранее видит, что движок скоро выберет форму (он смотрит вперёд на один период), поэтому точек выбора не пропускает и при 0.25 Гц.
- Цена редкого взгляда — только реакция: на 0.25 Гц мозг замечает руку или освободившийся организм через 4 с и перехватывает выбор движка раньше срока.
- **Итог: 1 Гц**:
  - реакция не хуже секунды почти даром (около 0.1 мс работы воркера на взгляд);
  - чаще смотреть бессмысленно — тело не успеет.

### 9. Представление морфологии

**Отпечаток** — около 40 чисел, никаких мешей:

- смесь форм — softmax движка над его латентом `z` по `SHAPE_SET` (или `ATTRACTORS`, `REGIMES`, `MORPHS`);
- 8 дескрипторов формы по реальному облаку узлов, не зависящих от положения и поворота:
  - размер, вытянутость, плоскость, асимметрия, скученность, вынос, бугристость;
  - закрутка — число полуоборотов вокруг длинной оси по срезам: у скрученной ленты около 1, у прямого стержня около 0;
- материал из 6 параметров — связность, жёсткость, демпфирование, отталкивание, память, рассеяние;
- число тел.

**Эмбеддинг**: расстояние Хеллингера по смеси (вес 0.7), стандартизованная геометрия (0.25; разброс берётся по собственным формам организма), материал и число тел (по 0.05). Евклидово расстояние в нём и есть морфологическая дистанция. Порог «радикальной» смены — 0.75: всё тело стало другой формой.

### 10. Память

- **Прототипы**: эпизодический архив с кластеризацией «по лидеру», радиус 0.3, до 96 форм. У каждого хранятся:
  - цель, которая к нему привела (смесь и материал);
  - когда был впервые и в последний раз, сколько раз приходил, сколько держался;
  - родитель, операция, энергия музыки;
  - оценка исполнителя (salience).
- **Вытеснение**: уходит наименее ценная форма, старая раньше недавней. Текущую и только что найденную не вытесняет никогда.
- **След**: последние 180 с — сколько форма держится, повторы, осцилляция A→B→A.
- **Тяга к возврату** — произведение нескольких множителей:
  - «созрела» — сигмоида после рефрактерного периода 45 с;
  - «держалась» — долго ли держалась форма;
  - «контекст» — похожа ли энергия музыки;
  - «устала» — 1 / (1 + недавние возвраты);
  - плюс оценка исполнителя.
  - Итог: вернуться можно, зациклиться — нет.
- **Глубина памяти** (ручка `memory`) масштабирует все постоянные времени от 20 с до 6 мин.

### 11. Новизна

Чистая арифметика: среднее расстояние предсказанного эмбеддинга кандидата до 4 ближайших запомненных форм. Давно виденные формы считаются дальше (полураспад 120 с × глубина памяти), поэтому старое снова становится новым.

Отдельные штрафы:

- **повтор** — приходы в окне;
- **осцилляция** — A→B→A;
- **бюджет радикальных смен** — полная смена тела не чаще раза в 20–60 с в зависимости от автономии и новизны;
- **давление разнообразия по видам операций** — не одно и то же превращение подряд;
- **«аппетит» к крупным событиям** — растёт со временем после последнего, сильнее при громкой музыке.

### 12. Кандидаты против прямого выбора

**Прямой выбор (D, E)**: Kev сам выбирает операцию («стать SPINE», «split», «остаться»).

- Геометрии он не видит, расстояний не считает, новизны не знает. У E есть сводка памяти словами, но посчитать новизну по ней он всё равно не может.
- Kev чувствителен к порядку вариантов: по его README ответ меняется у заметной доли вопросов, сколько именно у нас — меряет `--kev-bench`.
- Выбор может повторяться и не видит, как это будет выглядеть.

**Кандидаты (F, G)**:

1. Из собственного словаря организма получается 12–20 **допустимых** кандидатов (см. [словарь действий](#словарь-действий)).
2. Для каждого детерминированно предсказывается отпечаток — по функциям форм самого движка.
3. Каждый оценивается по 8 признакам: новизна, непрерывность, идентичность, соответствие руке, повтор, осцилляция, тяга памяти, радикальность.
4. В Kev уходят только 6 лучших с короткими словесными метками; Kev выбирает, уверенность решает, насколько ему верить.

Кандидаты лучше по всем пунктам: допустимость по построению, ограниченный вред от любого ответа, меньше токенов, всё измеримо.

**Чистая новизна (C) против G** показывает, почему оценка должна быть многокритериальной. C исследует почти так же, но теряет идентичность и чаще меняет всё тело целиком (таблицы ниже).

### 13. Отказы и откат

Движок **никогда не ждёт**.

- **Воркер**:
  - неблокирующий сокет, отдельный процесс;
  - нет ответа за 1.5 с (с Kev — за его таймаут + 0.7 с) — запрос брошен;
  - ответ, опоздавший сверх этого ещё на 0.5 с или пришедший, когда организм занят (уклоняется, рука лепит), выбрасывается;
  - падение воркера — перезапуск с паузой 2/5/15/30 с;
  - 5 отказов за 2 минуты — мозг сдаётся, организм живёт сам; выключить и включить — новая попытка;
  - битый ответ игнорируется.
- **Kev**:
  - таймаут 0.8 с, отказ или битый ответ → решает детерминированный арбитр;
  - низкая уверенность → тоже он;
  - не локальный адрес → Kev не используется.

Всё это проверено тестами:

- `kill -9` воркера → перезапуск;
- `SIGSTOP` (зависание) → таймаут, а тик движка не дольше 20 мс;
- битый, медленный или выключенный Kev — через **mock** API (ответы заготовлены, модели нет; он проверяет только клиент и пути отката);
- серия отказов → «сдаюсь».

Живой сеанс со сломанным воркером продолжается как обычно.

## Словарь действий

Взят из самих движков (`brain/vocab.py`), не захардкожен. Посмотреть: `python morphology_brain_test.py --vocab spear` (или `--vocab all`).

| Запрошено в задаче | Что есть в Myrmex | Как мозг это просит |
|---|---|---|
| expand / contract / inflate | формы с большим или малым `size`; материал DISPERSED ↔ COHESIVE | SHIFT/HYBRID к ним (метка «expand»/«contract»); DISSOLVE |
| elongate / compress / stretch | дескриптор `elong` (у Spear: SPINDLE, WINGS, STREAM против CORE, RING) | SHIFT/HYBRID («elongate»/«compress») |
| twist | дескриптор `twist`: полуобороты вокруг оси (у Spear больше всего у BLADES, SCYTHE) | SHIFT/HYBRID («twist»/«untwist») |
| fold / bend | отдельного параметра изгиба нет; Fold (v15) складывается физикой (CLAP, FURL, BLOOM); `clump` | EVENT; HYBRID («gather») |
| collapse | событие COLLAPSE (материал DISPERSED → REFORM) | EVENT, только при автономии > 0.6 |
| split / merge | события SPLIT и MERGE (стая, число тел) | EVENT |
| branch | формы TENDRILS, CROWN, THORN; дескриптор `reach`; SPROUT у Arbor | SHIFT/HYBRID («branch out»); EVENT |

| taper / thicken / thin | дескриптор `flat` | HYBRID («flatten»/«thicken») |
| ripple / distort | дескриптор `lumpy`; событие WAVE | HYBRID («ripple»); EVENT |

Метку направления (expand, twist…) получает каждый кандидат: по предсказанной геометрии берутся две самые сильные перемены дескрипторов в разбросе форм этого организма. Эти метки видит Kev, и они же в журнале.

## Автономия

Это не смешивание параметров. Автономия решает:

- **когда** мозг забирает решение у движка:
  - точки, где машина намерений движка сама выбирает следующую форму, мозг забирает с вероятностью, равной автономии — темп перемен остаётся темпом организма;
  - выше 0.6 мозг меняет форму и между этими точками, раз в 14 → 3 с (× persistence);
- **из чего** выбирать:
  - выборка кандидатов с весом идентичности выравнивается с ростом автономии;
  - COLLAPSE разрешён только выше 0.6;
- **как** выбирать:
  - вес идентичности 0.6·(1 − 0.5a);
  - вес руки 1.2·(1 − 0.6a);
  - бюджет радикальных смен 60 → 20 с;
  - температура арбитра растёт с автономией;
- **сколько уступать руке**:
  - когда рука лепит (Sculpt, Stasis-заморозка), мозг молчит всегда;
  - ниже 0.5 быстрая рука заставляет мозг уступить.

Шкала:

- 0 — только ты;
- 0.25 — лёгкие собственные мутации;
- 0.5 — пополам (по умолчанию);
- 0.75 — организм сильно исследует;
- 1 — почти сам по себе.

Влияние измерено свипом (ниже, «brain share» — доля перемен формы, которые последовали за решением мозга).

## MIDI и перчатка

- **Ручки-CC** из задачи: автономия, новизна, постоянство, сила мутации, возвраты, глубина памяти, частота.
  - «Нестабильность» у движка уже есть — это ручка `instability`, её не дублируем.
  - «Масштаб мутации» — это `brain_mutation`: доли гибридов, материал, сила.
- **Перчатка**: словарь существующий, новых жестов нет. Мозг читает то, что сессия уже знает о руке, как тенденции в пространстве дескрипторов:
  - раскрытость пальцев → больше или меньше (`size`, `clump`, `reach`);
  - вращение кисти → закрутка;
  - быстрое движение → давление новизны (вес новизны × (1 + 0.8·motion));
  - SPREAD → расширение, CLENCH → сжатие, PUSH → вытянуть, PINCH → локально (`lumpy`).
- **Что остаётся как было**: FLICK и остальные жесты вызывают свои события движка (`GESTURE_EVENTS`). В пресете Sculpt пальцы лепят форму сами, и мозг уступает.

## Уверенность Kev

- **Считается** как (p_max − 1/K)/(1 − 1/K) по перенормированным вероятностям предложенных кандидатов.
- **Политика** (`min_confidence` = 0.2):
  - уверенность ≥ max(0.5, min + 0.25) → выбор Kev;
  - между min и этим порогом → выборка из смеси (1 − c)·p_детерм + c·p_Kev («blend»);
  - ниже min → детерминированный арбитр.
- **Сила перемены**: оценка интенсивности от Kev (`score`, 0..3: subtle … radical) задаёт силу и время удержания.
- **Уверенность — не правильность.** Она решает только, какой вес отдать предпочтению Kev: каждый предложенный вариант уже допустим и оценён.
- **Пороги** подбираются по распределению уверенности на твоих данных (`--kev-bench`), а позже — по пометкам Good/Bad.

## Kev на Mac: как замерить D, E, F

```bash
# 1. сервер Kev (см. «Как включить»)
uv run --extra serve python -m kev.serve --run jaredpalmer/kev-0.8b --port 8009

# 2. из папки myrmex репозитория:
python morphology_brain_test.py --kev-bench --kev http://127.0.0.1:8009     # задержки, порядок вариантов, уверенность
python morphology_brain_test.py --benchmark --kev http://127.0.0.1:8009 --durations 5 30 --organisms spear colony
python morphology_brain_test.py --mode F --kev http://127.0.0.1:8009 --minutes 2   # журнал с вероятностями Kev

# то же Python-ом самого приложения, без репозитория:
M=/Applications/Myrmex.app/Contents
PYTHONHOME=$M/Resources/python PYTHONPATH=$M/Resources/app/src $M/MacOS/python3 -m myrmex.brain.bench --kev-bench --kev http://127.0.0.1:8009
```

`--kev-bench` проигрывает **настоящие** запросы мозга, записанные на 5 минутах песочницы. Он меряет:

- время на новое состояние и на то же из кэша;
- зависимость от числа вариантов (2–12);
- как часто перестановка вариантов меняет выбор;
- распределение уверенности и какую долю решений политика отдаст Kev, смеси и детерминированному арбитру.

Отчёты ложатся в `out/brain/`.

## Ограничения и что дальше

- Песочница — это логика движка, а не его физика. Дрожание (`jitter`) в ней считается по латенту; настоящая физика его фильтрует. На настоящем движке смотри `shape jitter`.
- Пороги диагнозов («застрял», «осциллирует»…) — оценочные, они записаны в `brain/metrics.py`. Сами метрики — сырые числа.
- Kev D/E/F здесь не запускался: веса недоступны в этой среде. Код, API и пути отката проверены против mock-сервера, но качество решений Kev нужно мерить на Mac.
- Дальше: дообучить Kev-0.8B на журналах решений и пометках Good/Bad (`kev.train --init_from`). Только после этого у Kev появится то, чего нет у детерминированного арбитра, — вкус исполнителя.
